# 智能路由全面验收报告（聊天 vs 方案识别）

- **验收对象**：cloudsol.cn Agent 模式路由智能（生产环境，commit `220b73a`）
- **验收时间**：2026-09-09 凌晨
- **核心诉求**：准确识别用户当前要干什么——什么时候走方案流程、什么时候聊天回复；支持同一对话内"前面聊天、中间传附件、后面要方案"的任意切换
- **结论**：**三层验收全部通过（本地 100 例 + 生产路由 28 例 + 多轮会话 5 场景），共发现并修复 6 类路由缺陷**

---

## 一、路由架构定稿（本轮确立）

**判定原则：路由判定只看用户原话，系统注入内容（图片描述/附件文本/记忆）只参与回答。**

| 用户输入特征 | 走向 | 附件/图片的角色 |
|---|---|---|
| 闲聊/感叹/个人事务（含行业词） | 通用直答（有温度、自然展开） | — |
| 聊天中传简历/文档求评价 | 通用直答 | 附件文本已注入，真实引用 |
| 明确方案诉求（方案动词+行业/场景） | 两阶段方案流程 | 附件内容可直接用 |
| 模糊方案诉求（"做个数字化方案"） | **澄清表单**（防凭空编方案，设计内） | — |
| 带具体规格的问价 | 两阶段+强制成本步（真 SKU 报价） | — |
| 纯问价/费用 | 轻量成本兜底（真 SKU 报价） | — |
| CRM 增删查 / KB 统计 / 导出 / 账户 | 对应专属分支（真数据） | — |
| 图片+求描述 | 直答 | vision 已"看"图 |
| 图片+方案诉求 | 方案流程 | vision 已"看"图 |

## 二、第一层：本地意图矩阵（100 例）

覆盖：礼节/账户/导出/竞品/方案/知识库/文件/成本/CRM/纯聊天/行业词闲聊/聊天↔方案转场/追问口语/短句歧义，共 15 类。

**结果：误判 19 → 0**（既有 56 例回归套件 0 失败），修复 5 类：

| # | 缺陷 | 例子 | 修复 |
|---|---|---|---|
| 1 | 行业词闲聊感叹被拉进方案（10 例） | "制造业不景气啊""钢铁价格涨了""医院挂号真难" | 行业词+无任务词/规模/动作 → 闲聊 |
| 2 | 账户词表缺词（4 例） | "我的邮箱是多少""密码忘了" | 词表补齐 |
| 3 | 导出词表缺词 | "帮我把结果生成 word 文档" | 补"生成+文档格式"，收紧防误吃方法论问句 |
| 4 | 竞品动词缺词（2 例） | "华为云 vs 移动云竞品分析""哪个强" | 补 vs/哪个强/竞品分析 |
| 5 | 价格提问被截进知识库 | "华为云服务器一年多少钱"走 RAG | 价格词排除，强制走成本真数兜底 |

## 六、边界与已知设计行为

1. **模糊方案诉求会弹澄清表**（"做个数字化方案"）——设计内，防凭空编造；带附件时例外（附件即需求来源）。
2. **带规格问价走两阶段+强制成本步**——2026-09-08 设计，保证报价为真数；纯问价走轻量兜底。
3. **附件文本单文件截断 15000 字**——超长部分 Agent 可用 read_customer_file 工具继续读全文。
4. **矩阵脚本已存档**（`.workbuddy/Temp/intent_matrix.py`），后续每次改 intent.py 都可一键回归。
