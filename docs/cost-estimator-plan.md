# 方案成本估算器 — 功能规划（已启动落地）

> 状态：**设计已收敛，落地中**。核心功能 = 「成本参考」+「成本对比」+ 常驻免责声明。
> 决策背景：匹配方案时用户关心「大概多少钱」，但精确报价是雷区（价格保鲜难、自由文本→BOM 抽取脆弱、精度/诚信风险撞「不编造」红线）。

---

## 一、核心设计（用户拍板，不做精确报价）

### 1. 成本参考（带默认值的可编辑账单）
- 基于**公开价目表**策展常见规格，给「低成本 / 均衡 / 高可靠」三档**月费区间参考**。
- 非实时爬取、不承诺准确，仅作量级参考。
- 数据来源：华为云官网公开页（产品页 / 官方帮助中心「资源和成本规划」），标注 `collected_at`，**切勿对外称「实时拉取价目表」**。

### 2. 成本对比（把定价权交回用户）
- 系统给出「方案含哪些产品 + 建议规格 + 参考价」的 BOM 骨架，用户**自填数量与单价**。
- 平台只做**加法汇总**与**方案 A vs B 并排比总价**，不做任何定价判断。
- 这比纯策展区间更抗面试追问：数字来自用户自己填的用量/单价，平台零幻觉。

### 3. 免责声明常驻
> 「本结果为参考估算，基于公开价目表策展，不含折扣与实时波动，实际价格以华为云官网价格计算器 / 销售报价为准。」

## 二、实现落点

- **数据**：`data/pricing_reference.json`
  - 字段：`product` / `spec` / `billing` / `price` / `source_url` / `collected_at`
  - 含按行业的 `profiles`（成本参考骨架：典型产品 + 建议规格 + 三档参考价）。
  - 商务定价产品（盘古大模型 / 华为云 Stack）标 `business_only: true`，前端显示「商务报价，请咨询华为云销售」，不出数字。
  - 注意：`data/` 被 gitignore，部署需单独 `scp` 到服务器 `/var/www/.../data/`。
- **后端**：`GET /api/pricing/reference?industry=通用` 返回价目 + 该行业成本骨架；`GET /api/pricing/industries` 返回支持行业。进程内缓存 + 文件 mtime 重载。
- **前端**：匹配结果页「方案内容」下方加「成本参考」卡片。
  - 按当前结果 `industry` 拉骨架，渲染可编辑 BOM 表（产品 / 规格 / 计费 / 参考价 / 数量 / 单价）。
  - 实时计算小计与合计；「低成本 / 均衡 / 高可靠」三档预设切换。
  - 方案 A vs B 并排比总价（v1 可仅做单方案编辑 + 合计，对比作为增强）。
  - 常驻免责声明。华为红主题，符合前端约定。

## 三、数据来源与红线

- 基础价目已采自华为云官网公开页，初稿见 `docs/pricing-reference-draft.md`（标 ⚠ 的 3 处待用户在官网价格计算器复核）。
- **全程不编造数字**：待核对清单（DataArts/ROMA/MRS/DLI/DWS/GaussDB 等）未获可靠公开价前只标「待核对 / 商务咨询」。
- 商务定价产品（盘古 / 华为云 Stack）前端一律不出数字，只提示咨询销售。

## 四、面试话术（备用，已与用户对齐）

> 「我没有做精确报价——华为云定价复杂、折扣多变，硬报一个数既不准又容易露馅。我做的是两件更务实的事：一是『成本参考』，基于公开价目表策展常见规格的低/中/高配区间，让用户心里有数；二是『成本对比』，方案的产品骨架和参考价由系统给，具体用量和单价让用户自己填，平台只做加法汇总和方案对比。最后常驻免责声明。这样既有用，又不踩诚信红线。」
