## 0. 现状与差距（代码级实测，非推测）

### 0.1 阶梯现状

| 阶 | 定义 | 现状 |
|---|---|---|
| **L1 模型选工具** | 仅 solution/competitor 进循环；短程（均 5 轮）；计划不绑定 | ✅ 已越过 |
| **L2 计划绑定 + 全意图** | 计划成为有齿的待办；所有意图进循环 | ✅ **已完成**（P0 `0171e4d` 前后）：A11 计划收敛率 1.000（21/21）、四类意图 legacy 全 0、零回退 |
| **L3 长程自愈** | 压缩后续跑；错误自愈；自写记忆 | ❌ **0/3 完成**（详见 §0.2） |
| **L4 自扩展委派** | 自建工具/技能；派生子 agent；按需挂 MCP | ❌ **0/4 完成**（详见 §0.3） |

### 0.2 L3 差距（逐条实测）

| 缺口 | 实测证据 | 结论 |
|---|---|---|
| **压缩从未真正执行** | n=30 全量活测 `compactions=0`；阈值 = `AGENT_CONTEXT_WINDOW 64000 × AGENT_COMPACT_AT 0.75 ≈ 48k` 估算 token，实测单请求远低于此 | 「压缩后续跑」**零证据**（A10 无法触发）。且 `compact_messages` 只有离线单测，没有"压缩后任务真的跑完了"的端到端证据 |
| **轮次上限太短** | `AGENT_MAX_TURNS=16`，实测均 5 轮 / 最长 12 轮 | 长程任务（≥30 轮）在当前配置下**必然被熔断**，谈不到 L3 |
| **墙钟预算会先卡死** | `AGENT_WALL_BUDGET=420`（7 分钟） | 16→64 轮后，按实测 ~26k tok/轮、~25s/轮，64 轮 ≈ 27 分钟 >> 420s → **墙钟先熔断**，抬轮次无意义。必须同步抬 |
| **错误自愈只有回填的一半** | `_exec_one` 把工具异常回填为 observation（C3 已做）；但 `_consecutive_tool_failures` **只计数、无策略** | 模型能"看到"错误，但宿主**不提供任何换策略信号**；也没有"同一工具连错 N 次 → 主动建议换路"的机制 |
| **自写记忆不存在** | `_maybe_save_episode`（`harness.py:1024`）是**宿主在任务结束后**自动编码落库；FC 的 `messages` 里没有任何记忆工具 | 模型**无法在任务进行中**记录"这个结论可复用"。且 `_maybe_save_episode` 有 `intent in (solution, competitor)` + `len(answer)>=300` 双门槛，P1 放开的新意图**一条都不会存** |

### 0.3 L4 差距（逐条实测）

| 缺口 | 现状代码 | 差距 |
|---|---|---|
| **自建工具** | `dynamic_tools.py::register_dynamic_tool`：只能把**已有工具**用 `steps` 串成 `dyn_*` 流水线（`_dig` 取值 + `_resolve_value` 传参），**不能产生新能力** | 没有"写一个带 schema 的可复用计算函数"的通道 → 无法表达"按我的定价模型算 TCO"这类**新能力** |
| **自建技能** | `skill_packs.py`：`data/skill_packs/*.json` **预置** 15 个包；`match_pack` / `match_capability` 由**宿主**按意图+关键词匹配 | 模型无法把一次成功的工作流**沉淀成新技能包**；宿主也不支持运行时热加载新包 |
| **派生子 agent** | `agents.py`（67 行）只是 **legacy 管线的提示词角色**（prompt + 工具子集，同一 ReAct 引擎）；`harness.py:886` 的"并行子体"实为**并行只读工具调用** | **真子体为零**：没有独立上下文、独立预算、独立终止判据的下级 agent，也没有父体收集结构化结论的机制 |
| **按需挂 MCP** | `mcp_client.load_mcp_servers()` 在**启动/首次运行**一次性读 `MCP_SERVERS` 全量注册 | 没有"列可用 server → 运行中按需挂载 → 卸载"的通道 |

### 0.4 ✅ 已有的关键地基（不要重造）

| 地基 | 位置 | 为什么它是 L4 的关键 |
|---|---|---|
| **每轮重建 tool schema** | `runner.py:165` `build_tool_schemas(harness.tools, extra=[TODO_TOOL_SCHEMA])` | **运行中注册的新工具，下一轮模型立刻可见** —— L4「自建工具 / 按需挂 MCP / 派生工具」全靠这条，已经具备 |
| 原生 function calling 传输层 | `models/llm.py::get_llm_with_tools` | 多轮工具协议已稳（含 thinking 分档、4xx 不重试） |
| 权限闸门 | `harness._gate_tool` + `permission_gate.py` | L4 所有"自扩展"动作都是写操作类 → 可直接挂 `ask` 闸门 |
| 计划机制 + 闭合门 | `runtime/todo.py` + `runner` 闭合门 | L3 长程的"进度锚点"；L4 子体的进度也可复用同一机制 |
| 情景记忆 + 画像 | `memory_profiles.py`（`agent_episodes` / `user_profile` / `playbooks`） | L3「自写记忆」的落库底座已存在，只缺"模型可调用的写入口" |
| 技能包挂载机制 | `skill_packs.py` `match_capability`（纯 JSON，加能力包不改代码） | L4「自建技能」只需把"写 JSON 包"变成模型可调用的工具 + 运行时热加载 |

## 1. 阶梯判据（每阶"做完了"的定义）

**判据必须是可测的，且不能自我循环（不能用"我说做完了"当证据）。**

| 阶 | 判据 | 指标 |
|---|---|---|
| L2 | 计划在交付时 100% 闭合；全部意图进入自主循环 | A11 ≥0.90 ✅ 已达标（1.000） |
| **L3** | ① 存在一个 ≥30 轮的公开任务，跑完且计划闭合；② 该任务触发 **≥2 次真实压缩**且压缩后**继续跑完**（不是压缩后崩）；③ 注入工具错误后 N 轮内**换策略并成功**；④ **第二次同类任务**注入并复用上次自写的记忆 | A10 压缩存活、**A12 长程完成率**、**A13 错误自愈率**、**A14 记忆复用** |
| **L4** | ① 模型自建的工具有 schema、可被**后续任务**调用；② 模型把一次成功工作流**沉淀为技能包**并在后续自动挂载；③ 父体**派生 ≥2 个子体**并汇总为单一交付物；④ 运行中**按需挂载**一个 MCP server 并使用其工具 | **A15 自建工具复用**、**A16 子体编排度**、**A17 按需挂载** |

## 2. L3（P2）设计：长程自愈

> 依赖顺序：**P2-1 容量 → P2-2 压缩 →（P2-3 自愈 / P2-4 记忆 可并行）**

### P2-1 长程容量（地基，必须先做）

**问题**：轮次 16 / 墙钟 420s 任一先到就熔断，长任务根本跑不到"长程"。

**改动**（`app/config.py`，一律 env 可覆盖）：

| 项 | 现值 | 目标 | 理由 |
|---|---|---|---|
| `AGENT_MAX_TURNS` | 16 | **64** | L3 判据要求 ≥30 轮任务；64 留一倍余量 |
| `AGENT_WALL_BUDGET` | 420 | **1800**（30 min） | 64 轮 × 实测 ~25s/轮 ≈ 27 min；不抬则墙钟必先熔断 |
| `AGENT_TOKEN_BUDGET_BY_INTENT` | solution 200k / competitor 500k | 长程意图 **+1 档**（新增 `long` 档，或把 competitor 提到 1M） | 64 轮 × ~26k/轮 ≈ 1.66M，现档位会在中途掐断 |

**边界纪律**：抬的是**天花板**，不是目标值；`snapshot()` 已能观测 `budget_ratio`，用数据决定是否再调。**必须先在 n=30 上复核"抬档后典型任务成本不变"**（中位数不动才是对的）。

**判据**：`AGENT_MAX_TURNS=64` 下跑一个自然 ≥30 轮的任务，`stopped_by=model`（不是 turns/tokens/wall），计划全闭合。

**风险**：长任务成本上升；失控循环烧钱。→ 用 `advisory_at=0.8` 的"请收口"提示先软收敛（已有），并保留硬上限。

### P2-2 让压缩真跑（A10 有证据）

**问题**：压缩代码在，但从未在真实任务里触发过 → 等于没有。

**改动**：
1. **先证伪自己的能力**：写一个必触发压缩的长任务（构造大检索结果 / 多轮大 observation），离线 + 真实 DeepSeek 各跑一次，断言 `compactions >= 2` 且**任务仍以 `stopped_by=model` 收敛**。
2. 修 `compact_messages` 的三个已知脆弱点（全部是我读码时确认的隐患，需实测确认）：
   - 压缩后 `messages[0]` 必须仍是原 system 政策块（`new_messages = [messages[0], note]`）—— 若 `messages[0]` 不是 system，政策块会丢；
   - 压缩**不得**切断 `assistant(tool_calls)` 与后续 `tool` 消息的配对（`_split_segments` 已按段切，但需用 `schema.message_shape()` 断言压缩后 `orphan_tool_calls` 为空）；
   - 压缩摘要调用的**失败路径**（`summary_text=""` → 硬截断）不得让任务失去"当前目标"（现在是塞一句"如需其中信息请重新检索"）→ 改为强制保留「用户原始诉求 + 计划状态 + 已完成步的结论」。
3. 压缩事件要能被**观测**：`trace.compactions` 已在 `fc_meta` 里 → 加进验收报告。

**判据**：≥2 次压缩 + 压缩后跑完 + 压缩后无孤儿 tool_calls + 终稿仍覆盖用户原始诉求。

### P2-3 错误自愈（从"能看见"到"会换路"）

**问题**：工具错误已回填，但模型可能反复撞同一面墙；宿主只计数不表态。

**改动**（宿主仍**不做决策**，只提供信号）：
1. 同工具连续失败 ≥2 次 → 注入一条**建议性**系统消息（与 `guards.advisory` 同构）："工具 X 已连续失败 N 次（原因：…）。建议换一个工具或换参数；若确认无替代路径，请在答案中如实说明该信息缺口。" —— **决策权仍在模型**。
2. 工具级**参数纠错提示**：`parse_tool_arguments` 已返回中文错误，补充"该工具的正确参数示例"（从 schema 自动生成），降低重试用例的重复率。
3. 把"自愈是否发生"变成**可测事件**：新增 `trace.heal_events`，记录 (失败工具, 失败次数, 后续是否换工具/换参, 是否成功)。

**判据（A13）**：注入式测试（工具第一次调用必然返回错误：如不存在的文件/非法参数）→ 模型在 **≤3 轮**内换策略并获得有效结果；批量 n≥10，A13 ≥0.80。

### P2-4 自写记忆（模型主动写，而非宿主事后写）

**问题**：记忆是宿主在任务结束后自动落库；模型在过程中无法记录。

**改动**：
1. 新增两个工具（**写操作，走 `ask` 闸门 + 审计留痕**）：
   - `memory_write(scope, title, content, tags)`：`scope ∈ {session, client, global}`。
     - `session` → 当前会话可复用结论；
     - `client` → 绑定 `client_id` 的客户事实（**必须带 client_id**，否则拒绝 —— 防串味）；
     - `global` → 用户级方法论/口径（如"我们公司报价一律含 3 年维保"）。
   - `memory_search(query, scope)`：主动检索，返回 top-k 与来源。
2. 落库复用 `memory_profiles` 的向量化能力（BGE + 余弦），新增表 `agent_notes`（`db_init.py` 建表 —— **按铁律：schema 变更需用户确认后才部署**）。
3. **注入纪律**：`scope=global/client` 的笔记在后续任务启动时按需注入（复用 `build_memory_context` 的通道）；`session` 只在同会话注入。**注入带来源标注**，模型必须能区分"我的笔记"与"知识库资料"。
4. **反幻觉**：`memory_write` 返回**宿主确认的落库结果**（成功/失败），并纳入 `verify.py` 的完成态核验事实表 —— 模型不得声称"已记住"而实际没落库（这是本项目踩过的坑的同一类）。

**判据（A14）**：任务 A 中写一条 `global` 笔记 → 新会话任务 B 的 system 里**确实出现**该笔记（可断言），且任务 B 的答案**引用了**它（人工/规则校验）。

## 3. L4（P3）设计：自扩展委派

> 四条能力互相独立，可分别开关。**全部默认惰性（env=0）**，逐条灰度。

### P3-1 自建工具（从"串流水线"到"造新能力"）

**现状**：`register_dynamic_tool` 只能组合已有工具。**新增**：

- `create_tool(name, description, params_schema, python_body)`：
  - 模型用 `run_python` 沙箱**验证**函数体可跑通 → 再注册为 `dyn_*` 工具；
  - 注册进 `harness.tools`（**下一轮即见**，地基已有）；
  - **持久化到用户级**（`data/user_tools/<user_id>.json`），后续任务可复用；
  - **安全**：沙箱白名单（无网络、无文件写、超时、内存上限），`ask` 闸门 + 审计；注册的工具**默认只读**，若声明为写操作需用户逐次确认。
  - **反注入**：工具描述与函数体由模型生成 → 必须是**数据**不是指令；宿主在注册时做静态检查（禁止 `eval/exec/__import__/open/网络`）。

**判据（A15）**：任务 A 自建 `dyn_tco_calc` → 任务 B **无需重建**即可调用它，且结果与宿主程序化计算一致（本项目铁律：**金额一律程序化产出**，自建工具也不得由 LLM 估金额）。

### P3-2 自建技能（把成功工作流固化成包）

**现状**：技能包是预置 JSON，宿主匹配。

**新增** `save_skill_pack(slug, triggers, role_block, steps_template, industry?)`：
- 输入：一次成功任务的**计划 + 工具序列 + 结论结构**（宿主从 `trace` 提取，模型补充抽象）；
- 产出：写入 `data/skill_packs/<slug>.json`，结构对齐现有 15 个包（`kind=capability` 走 `match_capability`，**加能力包不改代码**——地基已有）；
- **运行时热加载**：`skill_packs` 加缓存失效，无需重启；
- **质量控制**：新包必须能在**回放测试**里复现出不低于原任务的交付物（否则拒绝入库，防"垃圾技能"污染）。
- **去重/收敛**：同名/高相似包走"更新"而非"新建"。

**判据**：模型自建一个能力包 → 后续命中触发词时自动挂载（可断言 prompt 块存在）→ 交付物质量不低于原任务。

### P3-3 派生子体（真子体，不是提示词角色）

**现状**：`agents.py` 是提示词角色；`harness.py:886` 是并行工具。**真子体为零。**

**设计**（沿用"不引入第二套执行框架"的铁律）：
- 新增工具 `spawn_subagent(goal, tools, budget_turns, budget_tokens, deliverable_schema)`：
  - 子体 = **同一个 `run_loop`**，但**独立**的 `messages` / `RunGuards` / 计划 / `harness` 影子实例；
  - 子体**不继承**父体上下文（防污染），只拿到 `goal` + 允许的工具子集 + 必要的只读事实；
  - 父体拿回**结构化结论**（`deliverable_schema` 约束），而不是子体全文（防上下文爆炸）；
  - **并行**：父体一轮内可发起多个 `spawn_subagent` → 复用 `AGENT_PARALLEL_READONLY` 的并发通道。
- **预算隔离（关键）**：子体消耗必须计入父体总预算（防"套娃烧钱"）；子体自身有独立的 `turns_max`/`token_budget`，且父体有**最大子体数**（如 4）。
- **终止与失败**：子体失败 → 回填结构化错误给父体（同 C3 语义），父体自行决定重派/换路/如实说明。
- **可视**：SSE 新增 `subagent_start/update/end` 事件；前端 Plan 面板下挂"子体"分组（**只改 `agent_workspace.js/css`，不动 classic**）。
- **权限**：子体不获得父体未授予的工具；写操作仍需 `ask` 闸门（子体不能绕过人类确认）。

**判据（A16）**：一个需要对比 N 家竞品的任务 → 父体派生 ≥2 子体（每家一个）→ 汇总为单一交付物，且**总预算未超父体上限**、无"子体互相引用对方未完成结果"的混乱。

### P3-4 按需挂 MCP

**现状**：启动期一次性全量注册。

**设计**：
- 新增 `mcp_list_servers()`（列出**可用但未挂载**的 server，不含密钥）与 `mcp_mount(server)` / `mcp_unmount(server)`；
- `mcp_client` 支持**运行中**连接/注册（`register_remote_tools` 已可增量注册 → 下一轮 schema 即见，地基已有）；
- **懒挂 + 自动回收**：任务结束卸载（或保留 N 分钟）；未挂载的 server 的 tools **不出现在 schema**（省 token，这是"按需"的价值）；
- **安全**：server 名单来自服务端配置（**模型不能凭空创建 server**，只能从允许清单里选）；挂载是 `ask` 闸门动作。

**判据（A17）**：任务开始时 schema 里无该 server 工具 → 模型调用 `mcp_mount` → **下一轮**工具可用并成功调用 → 任务结束后已卸载。

## 4. 指标与门禁（新增，不侵占既有 A1–A11 口径）

| 指标 | 定义 | 线 |
|---|---|---|
| **A10** 压缩存活 | 触发 ≥2 次压缩的任务仍以 `stopped_by=model` 收敛且计划闭合 | 有证据（当前"未触发"） |
| **A12** 长程完成率 | ≥30 轮任务完成（计划闭合 + `stopped_by=model`）占比 | ≥0.80 |
| **A13** 错误自愈率 | 注入工具错误后 ≤3 轮换策略并成功 | ≥0.80 |
| **A14** 记忆复用率 | 第二次同类任务注入了上次自写笔记且答案引用 | ≥0.80 |
| **A15** 自建工具复用率 | 自建工具在**后续任务**被调用且结果与程序化基准一致 | 100%（金额类必须一致） |
| **A16** 子体编排度 | 需委派任务中父体派生 ≥2 子体并汇总 | ≥0.80 |
| **A17** 按需挂载 | 运行中挂载 MCP 并使用其工具 | 有证据 |

**门禁**：任一指标低于线 **禁止转默认**（沿用 S4 结论的纪律）；既有 `regress_all.py`（意图 100/100 + 沙箱 16/16）与新离线套件必须全绿。

- **M4（L4 委派）**：+ P3-3（子体）→ A16 达标；P3-2（自建技能）作为收尾。

## 6. 风险与回退矩阵

| 风险 | 表现 | 缓解 | 回退 |
|---|---|---|---|
| 长程烧钱 | 64 轮 × 1.6M token 单任务 | advisory 软收敛 + 硬上限 + 按意图分档 | `AGENT_MAX_TURNS=16` / `AGENT_WALL_BUDGET=420` |
| 压缩后丢目标 | 压缩摘要没抓住用户诉求 → 跑偏 | 强制保留"原始诉求 + 计划状态 + 已完成结论"；`message_shape` 断言无孤儿 | 调大 `AGENT_COMPACT_AT` / 关压缩 |
| 自建工具成攻击面 | 模型写入 `open()` / 网络调用 | 沙箱白名单 + 静态检查 + `ask` 闸门 + 用户级隔离 | `AGENT_AUTO_TOOLS=0` |

| 子体套娃烧钱 | 子体再派子体，预算失控 | 子体预算计入父体 + 最大子体数 + 禁止子体再派（默认） | `AGENT_SUBAGENTS=0` |
| MCP 越权 | 挂载未授权 server | 只允许服务端白名单 + `ask` 闸门 + 结束后卸载 | `AGENT_MCP_ONDEMAND=0` |
| 与 classic 互污染 | 前端串味 | 只动 `agent_workspace.js/css` + `index.html`，classic 字节级不动 | 前端版本号回退 |

## 7. 明确不做的事（边界）

1. **不让模型直接改自身代码**（P5 才谈，且需分级放权 + 灰度）。
2. **不让模型凭空创建 MCP server**：只能从服务端允许清单里选。
3. **金额一律程序化产出**：自建工具可以算，但金额必须走程序化成本表，LLM 不碰数字。
4. **子体默认不能再派子体**（深度=1），防止无限递归。
5. **不为了指标而指标**：A12–A17 全部要求"有活测证据"，不接受离线模拟当验收。
