# cloudsol.cn 面试备战手册

> 适用岗位：ToB 解决方案 / 售前工程师（非技术面试）
> 使用方式：每条内容都给「技术版」（你懂原理）和「人话版」（面试说给外行听）。
> 非技术岗面试核心心法：**先讲业务价值，再打生活比喻，最后一句收业务。** 技术名词能不冒就不冒。

---

## 一、项目一句话定位（背到脱口而出）

- **技术版**：cloudsol.cn 是一个基于 FastAPI + ChromaDB 向量库 + DeepSeek LLM 的华为云解决方案智能匹配系统，支持标准 / 智能 / 向导三种匹配模式，已上线部署。
- **人话版**：这是一个给华为云销售和售前用的 AI 助手。销售把客户需求说一句话，它就能从几百个方案里找出最匹配的，自动生成一份结构化的解决方案，还顺带对比竞品。原本要花几小时写的方案，现在几分钟搞定。

---

## 二、项目背景与痛点

- **技术版**：华为云方案覆盖 17 个行业、数百产品，销售 / 售前每次需人工从零拼装方案，依赖个人经验、效率低、质量不稳定。系统将方案知识沉淀为可检索的知识库，用 LLM 做需求理解 + 方案生成。
- **人话版**：华为云的方案太多了，一个销售根本记不住。每次见客户，都要从零开始手搓一份方案，费时，而且不同人写出来的质量还不一样。这个工具把公司积累的"方案经验"集中管理，新人也能写出老手水平的方案，还能当场跟客户讲清楚"我们和友商比强在哪"。

---

## 三、技术栈总览（双语言对照）

| 层 | 技术 | 人话解释 |
|------|------|------|
| 后端框架 | FastAPI + Uvicorn | 负责接收请求、调 AI、返回结果的服务 |
| 向量数据库 | ChromaDB | 存"方案意思指纹"的库，支持按意思找方案 |
|  embeddings | BGE-small-zh | 把中文文本转成"意思向量"的模型 |
| 大模型 | DeepSeek API | 负责理解需求、写方案的语言模型 |
| 前端 | 原生 JS SPA + Nginx | 网页界面，前后端分离 |
| 用户库 | SQLite | 存账号、收藏、历史 |
| 部署 | 阿里云 + systemd + HTTPS | 放在云服务器上跑，带自动守护 |
| 皮肤 | CSS 变量 + data-skin | 一键换 4 套配色 |

## 四、系统架构（双语言）

**技术版（分层）**
```
前端(原生JS SPA) ──HTTP/SSE──> FastAPI 路由层
                              ├─ 标准模式: SolutionMatcherService.generate_enhanced
                              ├─ 智能模式: SolutionAgent(Harness + Tools + Memory)
                              ├─ 向导模式: 前端收集结构化需求 → 标准匹配
                              ├─ 知识库: KnowledgeBaseService(ChromaDB)
                              ├─ 用户系统: AuthService(SQLite)
                              └─ 导出: Word 报告生成
                            ↓
                      ChromaDB 向量库 / SQLite / DeepSeek API
```

**人话版**
把系统想成一家"方案事务所"：
- **前台（网页）**：销售在里面说需求、看方案。
- **顾问（AI 引擎）**：听清需求后，去档案室翻资料，再写出方案。
- **档案室（知识库）**：几百份华为云真实方案，按"意思"归档，随查随取。
- **后勤（部署）**：整套事务所在云上 24 小时营业，挂了自动重启。

## 五、核心功能模块（每个双版本）

### 5.1 三种匹配模式
- **技术版**：
  - 标准模式：向量检索 Top-K → LLM 按 14 章固定结构增强生成。
  - 智能模式：SolutionAgent 驱动 ReAct 循环（analyze_demand → search_kb → search_competitor → 生成），SSE 实时推送思考流。
  - 向导模式：前端 4 步收集行业 / 规模 / 痛点 / 确认，合成需求描述后走标准匹配。
- **人话版**：给不同水平的销售用。熟手直接打字说需求；想省心就让 AI 自己一步步查资料再写（还能看到它"思考过程"）；怕说不清的，用向导像填表一样把客户情况点出来，系统帮着生成需求。

### 5.2 知识库管理（用户独立）
- **技术版**：每个用户拥有独立文档目录 + 独立 ChromaDB collection，通过 contextvars 传 user_id 隔离；支持在线增删改文档、单文件重索引。
- **人话版**：每个销售登录后看到的是自己的资料库，自己存的竞品分析别人看不到，像每人一个独立工作台。也能在线增删方案文档，改完一键重新建索引。

### 5.3 竞品对比
- **技术版**：search_competitor 检索 12 家竞品厂商（AWS / Azure / 阿里云等）资料，与华为云方案做对比生成。
- **人话版**：客户常问"你和阿里云比怎么样"，系统能调出对应竞品资料，生成一段客观对比，帮销售在客户面前做差异化论证，不冷场。

### 5.4 方案导出
- **技术版**：/api/export/report 将匹配结果生成 Word(.docx) 报告，含方案正文 + 来源文档 + 元数据，支持容错（字段缺失不 500）。
- **人话版**：生成好的方案能一键导成 Word 文档，销售可以直接发给客户或改一改就用，不用复制粘贴。

### 5.5 用户系统
- **技术版**：AuthService 实现注册 / 登录 / 验证码 / session（JWT + token_version 防失效），SQLite 存 users / favorites / history 表。
- **人话版**：销售用手机号注册登录，系统记住他的收藏和历史方案，下次接着用。

### 5.6 数据仪表盘
- **技术版**：/dashboard/stats + /knowledge/stats 聚合文档数、行业覆盖、行业分布图表（Canvas 渲染）。
- **人话版**：一个数据看板，告诉销售"知识库现在有多少方案、覆盖多少行业"，用图一看就明白家底。

### 5.7 移动端体验
- **技术版**：@media(max-width:767px) 内重构，5 Tab 底部导航（匹配 / 竞品 / 仪表盘 / 知识库 / 我的），"我的"聚合页 + 子页独立返回导航条，成就 3 列，页面切换淡淡上滑。
- **人话版**：手机上也能用，底部五个按钮切换功能，操作跟常用 App 一样顺手，出门见客户掏手机就能查方案。

### 5.8 皮肤系统
- **技术版**：4 套 CSS 变量皮肤（经典蓝 / 浅葱绿 / 盛夏黄 / 桃桃粉），data-skin 联动，偏好持久化。
- **人话版**：界面能换 4 种配色，销售挑自己喜欢的，用着舒服。

## 六、关键技术点深挖（双版本，技术面追问底线）

### 6.1 向量检索
- **技术版**：BGE-small-zh 把方案文本编码为稠密向量存入 ChromaDB；用户需求同样编码，用余弦相似度召回 Top-K。用户级 collection 隔离。
- **人话版**：给每篇方案提取"核心意思指纹"。客户说一句话，系统也提取指纹，去和所有方案比对，找意思最贴近的几篇。它搜的是"意思"不是"关键词"——客户说"工厂设备总坏"，它能关联到"设备预测性维护方案"，哪怕字面没提。

### 6.2 ReAct 编排（智能模式）
- **技术版**：自写 AgentHarness 驱动 Thought→Action→Observation 循环；用正则从 LLM 文本解析 Action（非 function calling）；max_steps=8，超时 120s，失败走 _generate_fallback 模板兜底。
- **人话版**：让 AI 像顾问一样工作：先想清楚要查什么 → 去查 → 查完再想还缺什么 → 再查 → 最后综合成方案。不是凭空编，而是"先想、再查、再想、再写"。我设了最多 8 步上限，防止它绕圈停不下来。

### 6.3 LLM 稳定性
- **技术版**：LLM 调用 3 次重试 + 120s 超时 + fallback 降级；接口异常时返回模板方案而非空结果。
- **人话版**：AI 接口偶尔会卡。我加了三道保险：卡了自动重试；超时就放弃等待；还是出不来就用预设模板先给客户一个基础方案，保证页面永远不白屏、永远有东西。

### 6.4 防幻觉
- **技术版**：增强管线强制方案基于检索到的真实文档，14 章固定结构 + 每段来源绑定（source_documents）。
- **人话版**：AI 最大的毛病是"一本正经胡说"。我的做法是逼它必须基于知识库里真实的华为云文档来写，每段方案都能指出"出自哪篇资料"。相当于给 AI 发了规矩：不准脱离参考书自由发挥。

### 6.5 用户隔离
- **技术版**：contextvars 传 user_id，KnowledgeBaseService 按 user_id 路由独立 collection 与文档目录。
- **人话版**：每个销售的数据互相看不见，像每人一个带锁的抽屉，安全和隐私都有保障。

## 七、高频面试题库（分类，每题双版本）

### A. 项目动机类
**Q：你为什么做这个项目？**
- 技术版：观察到华为云方案知识分散、售前人工拼装方案效率低，用 RAG + LLM 可做自动化匹配。
- 人话版：我实习 / 关注 ToB 销售场景时发现，售前写方案太费时间、又依赖个人经验。我想做个工具把公司的方案知识沉淀下来，让任何人都能快速产出专业方案，这正好是我想去的方向。

### B. 技术实现类
**Q：你这个 AI 怎么保证方案靠谱、不瞎编？（最常考）**
- 技术版：两道防线——(1) 生成必须基于检索到的真实文档，source_documents 绑定；(2) 接口异常自动降级模板。超时 / 重试保护。
- 人话版：我做了三件事。第一，划范围——AI 只能基于我们真实的华为云文档写，像考试只能翻指定参考书。第二，可追溯——每段方案能指出出自哪篇资料，销售见客户心里有底。第三，兜底——AI 出问题就自动给模板方案，绝不空白或错误。我的目标不是 AI 多聪明，而是**销售敢不敢拿去见客户**。

**Q：如果不懂技术，你怎么跟开发同事协作？**
- 人话版：我把需求拆成"销售要什么结果"，用接口文档和原型跟后端对齐；技术上我能读得懂代码逻辑、能自己排简单 bug（比如之前定位到接口 404 是路由斜杠问题），所以沟通成本很低。

### C. 业务 / 售前类
**Q：这个工具给销售带来什么实际价值？**
- 技术版：需求→方案自动化，知识库沉淀，竞品对比结构化。
- 人话版：三件事。一是**快**——几分钟出方案，不用熬夜手搓；二是**稳**——新人也能写出老手水平，不依赖个人经验；三是**能打**——自带竞品对比，客户问"你和友商比咋样"当场就能答。本质是把个人能力变成组织能力。

**Q：你怎么理解售前 / 解决方案这个岗位？**
- 人话版：售前是"翻译官"——把客户的业务痛点翻译成技术能实现的方案，再把技术价值翻译成客户听得懂的业务语言。这个项目的本质就是帮售前把第二步（生成方案）标准化、提速。

### D. 个人 / 行为类
**Q：这个项目你主导了多少？**
- 诚实版：从需求分析、架构设计到前后端实现和部署都是我独立完成并上线的；其中 LLM 编排参考了行业通用的 ReAct 思路做了适配。我能讲清每一个模块为什么这么设计。

**Q：遇到最大的难点是什么？**
- 见第八节 STAR 案例。

## 八、STAR 案例（2 个真实难点，背熟）

### 案例 1：收藏接口 404 排查
- **S（情境）**：项目上线后，控制台一直报 404，收藏功能拉不到数据。
- **T（任务）**：定位并修复，不能影响其他接口。
- **A（行动）**：用 curl 逐一测路由，发现带斜杠 `/favorites/` 返回 401（正常），不带斜杠 `/favorites` 返回 404。定位到后端子路由定义用了 `@router.get("/")`（带斜杠），但前端调用不带斜杠，FastAPI 子路由不自动补全。把路由路径从 `"/"` 改成 `""` 解决，history 接口同类问题一并修复。
- **R（结果）**：404 消失，收藏 / 历史功能正常，控制台干净。

### 案例 2：移动端底部留白与样式陷阱
- **S（情境）**：手机端"我的"页底部信息沉不下去，贴着内容。
- **T（任务）**：让底部信息始终沉到最底下。
- **A（行动）**：先误用错选择器，后用 flex+margin-top:auto，仍不生效。经查是 style.css 里 `.page.active{min-height:0!important}` 用 !important 压过了我的规则。改为 ID 选择器 + 自身 !important 才压过。
- **R（结果）**：footer 稳定沉底，理解了 CSS 层叠优先级，同类问题以后一眼能定位。

## 九、避坑红线（务必遵守）

1. **Harness 不是自主 Agent**：准确说法是 agentic workflow / 工具增强生成引擎。三个工具全是只读检索 + 文本生成，无外部状态变更。简历和口述都别写"自研 Agent"。
2. **不编造量化数字**：可讲"几分钟 vs 几小时"的逻辑推导，但别编"效率提升 80%"这种精确值，被追问来源就露馅。
3. **文档数字要对得上**：170 篇华为云文档 + 120 篇竞品文档（12 家厂商）+ 276 向量片段。被问"哪来的"就答官网公开方案页。
4. **参与 vs 主导诚实划界**：能讲清"为什么这么设计"的才是你的；参考通用思路的如实说"参考并适配"。
5. **密码框警告可忽略**：浏览器提示密码框没包 form，不影响功能，面试不用提。

## 十、3 分钟项目陈述稿（完整背稿）

"我先讲是什么。cloudsol.cn 是一个给华为云销售和售前用的 AI 方案助手。销售把客户需求说一句话，它就能从几百个方案里找出最匹配的，自动生成结构化解决方案，还顺带对比竞品。原本几小时的手工活，现在几分钟。

为什么做？华为云方案覆盖 17 个行业、几百个产品，销售根本记不住，每次见客户都从零手搓方案，费时且质量不稳。我想把公司的方案经验沉淀成知识库，让新人也能写专业方案。

怎么做的？技术上我用 FastAPI 做服务，ChromaDB 向量库存方案'意思指纹'，DeepSeek 大模型理解和写方案。核心有三个亮点：第一，它搜的是'意思'不是'关键词'，客户说'设备总坏'能关联到预测性维护方案；第二，智能模式下 AI 像顾问一样先想再查再写，还能看到思考过程；第三，我重点防 AI 胡说——逼它只基于真实文档写，每段能溯源。

举个小例子证明我真做过：上线后收藏功能报 404，我查出来是后端路由带了斜杠、前端调用没带，FastAPI 不匹配，改路由定义就修好了。

业务价值上，它帮销售三件事：快、稳、能打——出方案快，新人水平稳，竞品对比帮销售在客户面前做差异化。

目前项目已上线 cloudsol.cn，真实可访问可演示。这就是我的项目，谢谢。"
