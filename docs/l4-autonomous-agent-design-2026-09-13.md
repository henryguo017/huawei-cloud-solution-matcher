## 1. 定位：两层都要 —— 通用底座 + 垂直售前包

目标是**完全自主的售前 Agent**：不是"能力面铺得很宽的通用助手"，也不是"只能按固定流程跑的脚本"。
落地形态是**双层**：

| 层 | 是什么 | 与行业的关系 |
|---|---|---|
| **通用底座** | 自主循环、计划/待办机制、子体派生、记忆 API、工具注册与自扩展、守卫与审计 | **行业无关**。换包即另一个垂直 |
| **垂直售前包** | 售前资产、售前工具、售前角色子体、售前阶段语义 | **只服务售前** |

**判据：自主度是手段，售前闭环是本体。** 一个任务从线索到交付物 + 推进建议，全程不需要人喂下一步。

### 自主度阶梯（现状 → 目标）

| 档 | 特征 | 位置 |
|---|---|---|
| L0 流水线 | 宿主写死步骤（legacy 两阶段，今天线上默认） | — |
| **L1 模型选工具** | 仅 `solution`/`competitor` 进循环；短程（均 5 轮）；计划**不绑定** | **← 现状（S4 验证到此）** |
| L2 计划绑定 + 全意图 | 计划成为有齿的待办；所有意图进循环 | 目标 P0/P1 |
| L3 长程自愈 | 压缩后续跑；错误自愈；自写记忆 | 目标 P2 |
| L4 自扩展委派 | 自建工具/技能；派生子 agent；按需挂 MCP | 目标 P3 |

## 3. 双层边界（什么属于哪一层）

| 能力 | 归属层 | 理由 |
|---|---|---|
| 自主循环 / 终止判定 / 预算熔断 | 通用底座 | 与任务内容无关 |
| **计划/待办机制 + 闭合门（P0）** | **通用底座** | "做事有始有终"是任何任务的通则 |
| 子体派生、记忆读写 API、工具注册与自扩展 | 通用底座 | 引擎能力 |
| **售前阶段语义**（客户画像→需求识别→方案匹配→竞品对标→报价/TCO→交付物+跟进） | **垂直包** | 由包注入默认骨架，模型可改写 |
| 售前资产（客户档案 / 行业包 / 竞品库 / 成本报价模型 / 案例库 / 打法库） | **垂直包** | 领域知识 |
| 售前工具（`search_kb` / `search_competitor` / `cost_calc` / CRM / 招标线索） | **垂直包**（经 MCP + 工具注册表挂载） | 领域动作 |
| 售前角色子体（客户分析师 / 竞品分析师 / 方案撰写 / 报价） | **垂直包** | 领域分工 |

**挂载机制复用既有资产**：技能包（`match_pack` / `match_capability`）+ MCP（`cost_calc` / `crm`）已经是"插拔"的雏形，不需要新造。

## 4. P0 详细设计（计划绑定）—— 已实现

### 4.1 语义变更

计划从**叙述性**（给用户看的进度视图，明确"不约束执行"）改为**有齿的待办**：

- 终稿交付前，计划里**每一步必须闭合**：`done`，或 `skipped`（**必须带原因**）。
- 有未闭合项时，宿主**不接收终稿**，把未闭合项退回给模型，由模型自决：**补做**，或**如实标 skipped**。
- 新增 `skipped` 状态 = 允许放弃，但必须**显式声明**——不允许"默默不收尾"。

### 4.2 边界纪律（这不是宿主夺权）

宿主**只做一件事**：查「模型自己发布的计划有没有未闭合项」这一个事实。然后给模型**两个选项**。

宿主**不做**：
- ❌ "某工具属于哪一步"的归属推导（那正是架构文档 §8 要删的 `_tool_to_plan_index`）
- ❌ 规定执行顺序（顺序仍完全由模型决定）
- ❌ 替模型决定补做还是跳过

### 4.3 实现清单

| 文件 | 改动 |
|---|---|
| `app/config.py` | `AGENT_PLAN_CLOSE_ENFORCE=1`、`AGENT_PLAN_CLOSE_MAX_RETRY=2` |
| `app/agent/runtime/todo.py` | 状态词表加 `skipped` 及近义词；schema 描述改为"待办 + 收尾前须闭合"；新增 `open_steps()` / `closure_summary()` / `build_close_instruction()` |
| `app/agent/runtime/runner.py` | 终稿分支加**闭合门**：未闭合且未达上限 → 注入交回提示并 `continue`；`plan_all_done` 改为**闭合**判定（done/skipped）；`trace.plan_drift_rejections` 计数 |
| `app/agent/runtime/context.py` | POLICY 两条硬性要求：①连续工具调用 ≥2 次无计划必须补发；②**交付前计划必须闭合**，禁止虚标 done |
| `app/agent/harness.py` | `fc_meta` 增 `drift_rejections` / `plan_open_at_final` |

### 4.4 防死锁

最多交回 `AGENT_PLAN_CLOSE_MAX_RETRY`（默认 2）次；超出则**接受终稿并打告警标记**——
原则：**宁可告警，不可卡死**。代价：仅在发生漂移时多 1–2 次 LLM 调用。

### 4.5 验收

- **离线**：`.workbuddy/Temp/fc_runtime_smoke.py` **44/44 通过**（新增 8 项 P0 检查）
  - `T10` 计划留 1 步未闭合 → 断言：拦截 1 次、模型改为 `skipped` 后交付、共 5 次 LLM 调用
  - `T10b` 模型死不闭合 → 断言：拦截恰为上限 2 次、**仍产出终稿**（不死锁）
  - 附带验证：计划全闭合后 thinking 自动降档（`enabled → disabled`），证明 `skipped` 被正确当作闭合信号
- **新增指标 A11 计划收敛率** = 交付时计划全闭合的运行 / 发布过计划的 FC 运行，目标 **≥0.90**
- **待办**：本地活测（需拉起重启服务）——给一个多步售前任务，确认出现「模型**自己**发现漏步并补上」的行为，而不是靠改提示词

### 4.6 回退

`AGENT_PLAN_CLOSE_ENFORCE=0` + restart → 行为回到今天。**经典模式与 legacy 管线一行未动。**

## 5. 后续路线

| 阶段 | 内容 | 判它做完的标准 | 动生产 |
|---|---|---|---|
| **P1 取消范围门** | 全意图进循环（含 data/knowledge/闲聊），由模型判断"要不要动手"；确定性分支降级为"模型选择不调工具" | 50 题路由 0 回归；闲聊不退化成流水线 | 否 |
| **P2 长程** | 轮次上限 16→64；压缩真正跑通（A10 有证据）；任务状态持久化 + 服务重启续跑 | 跑通一个 ≥30 轮、触发 ≥2 次压缩的任务 | 否 |
| **P3 子体 + 自记忆 + 自评收尾** | **并行子体从 legacy 迁进 FC 并工具化**（`harness.py:853` 已有实现，改造成"虚拟售前小组"）；任务中可自写记忆；质量门由"宿主告警"改"模型自评 + 宿主审计" | 同一任务模型自行派生 2 个子体并汇总；第二次同类任务明显复用上次经验 | 否 |
| **P4 垂直包成型** | 售前资产 + 售前角色子体预设 + 售前阶段模板 + 售前指标接入 | 一条商机端到端无人喂 | 否 |
| **P5 分级放权** | 改自身代码 / 对外发送按 §2 逐级放开 | 每级灰度无事故 | 是（灰度） |

| A9 计划自治度 | >0 | 0.533 ✅ |
| A10 压缩保真 | ≥0.90 | 未触发 ⚠️ |
| **A11 计划收敛率（P0 新增）** | **≥0.90** | 待活测 |

### 6.2 销售口径（新增，垂直版必须补）

A1–A11 只回答"它是不是真 agent"，**回答不了"它是不是称职的售前"**。垂直版必须加：

| 指标 | 定义 | 为什么重要 |
|---|---|---|
| **S1 交付物可直用率** | 交付的方案/对比矩阵，无需人工改写即可对客的比例 | 售前只看"能不能直接发出去" |
| **S2 商机推进步数** | 一次会话中模型自主推进的售前阶段数（无需人喂下一步） | 直接度量"自主"的业务价值 |
| **S3 资产复用率** | 同类客户第二次会话相对第一次的耗时/工具调用下降幅度 | 证明客户与打法记忆真的生效 |

## 7. 风险与前提

| # | 风险 / 前提 | 对策 |
|---|---|---|
| R1 | **模型是天花板**：L1 均 22s/5 轮；L3/L4 是分钟级 + 几十轮，DeepSeek 长程稳定性未知 | D-C 先实测；必要时换底座或加"自检-重规划"回路 |
| R2 | **成本与时延** | 预算守卫 + 分级放权；长任务单列预算策略 |
| R3 | **公开站 + 写权限 = 真实攻击面**（cloudsol.cn） | 守卫不可省：预算熔断、权限门、全量 trace、一键关闭 |
| R4 | **计划闭合门可能被"虚标 done"绕过** | POLICY 明确禁止 + 提示词要求如实标 skipped；后续可用"工具序列 vs 计划"抽检（需谨慎，勿变成宿主夺权） |
| R5 | 改自身代码 / 对外发送不可回滚 | §2 分级放权，绝不一步到位 |
| R6 | 垂直包与底座耦合，日后换垂直被污染 | §3 边界纪律：领域语义只准进包，不准进底座 |

**回退（全局）**：`AGENT_RUNTIME=legacy` + restart，或前端 ⚡ 自主开关关闭（双门禁 `runtime=fc` 且 `autonomy=high`）。
