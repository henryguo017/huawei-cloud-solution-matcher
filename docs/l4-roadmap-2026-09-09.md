## 0. 先回答质疑："这真的能达到 L4 吗？"

**诚实的回答分三层：**

### 0.1 "L4"不是玄学，拆成 6 个可测行为指标（A1-A6）

| 指标 | 定义 | 判定线 | 由谁验收 |
|---|---|---|---|
| A1 自主拆解率 | 30 例裸目标（不给路由提示）产出可执行计划的比例 | ≥70% | T5.1 盲测 |
| A2 工具组合深度 | 自主模式下平均每任务工具链式调用次数 | ≥2 | 轨迹统计 |
| A3 经验增益 | 相似任务第 2 次执行 vs 第 1 次：成功率↑ 且 时延↓ | 对照实验显著 | T5.3 基线对照 |
| A4 长程存活率 | 定时任务 7 天按时执行率 | ≥95% | job_runs 统计 |
| A5 安全零事故 | 沙箱逃逸 / 越权 / 预算超限 | =0 | 攻击用例 + 审计 |
| A6 稳定性不倒退 | 既有 50q + 100 例矩阵回归 | 0 失败 | 回归脚本 |

**方案是否"L4"不由我宣称，由 A1-A6 的数据判定。** 这正是 P0 先建评测的原因：没有这些数字，任何"L4"都是嘴上说说。

### 0.2 三个诚实的边界（说在前面）

1. **模型能力是最大变量。** 自主拆解的上限取决于 DeepSeek v4-pro 的长程规划能力，这是本方案唯一不受代码控制的因素。对策：A1 盲测若 <50%，启用"混合降级"——自主计划失败 2 次自动回退现有 L3 路由（T1.4 内建），产品价值不归零。
2. **真正的"自我进化"（L5）不在本方案。** 自动改写自己的提示词/策略属于 L5，需要 DSPy 类离线优化或训练，本方案只做到"经验检索注入 + 人工审定 playbook"，这是 L4 与 L5 的分界线，不越界宣称。
3. **经验增益依赖任务重复性。** 你的场景（方案生成、竞品分析）任务模式高度重复，A3 有天然优势；若做全新任务类型，经验块可能是噪声——所以注入块带相似度阈值（<60% 不注入）。

### 0.3 结论

本方案给出 L4 的**完整架构 + 判定体系 + 降级路径**。架构五要素（自主拆解/动态工具/经验记忆/长程主动/可控可测）全部有实装路径且代码锚点已核对；行为是否达标由盲测数据说话。**预期：P1 结束 A1 在 55-75% 区间（模型强则上限高），A2/A4/A5 是工程问题必然达标，A6 由门禁保证。**

## 2. WS1 动态工具层（详细规格）

### T1.1 沙箱代码执行 `run_python`

**接口契约**（注册为普通 Tool，走现有闸门）：
```python
Tool(
  name="run_python",
  desc="在受限沙箱中执行 Python 代码片段。用于精确计算、数据整理、格式转换等"
       "无法用现有工具完成的任务。代码将通过 stdin 传入，print 输出结果。",
  params={"code": "str, 必填, ≤8000 字符"},
  handler=sandbox_handlers.run_python,
)
# 返回: {"ok": bool, "stdout": str(≤4KB 截断), "stderr": str(≤1KB), "elapsed": float}
```

**执行模型**（生产 = Linux ECS，安全机制全部可用）：
1. `subprocess.Popen([sys.executable, "-I", "-c", ...])` —— `-I` 隔离模式：不加载 site/user env，不继承 PYTHONPATH
2. `preexec_fn` 内 `resource.setrlimit` 五重限制：
   - `RLIMIT_CPU=5s`（死循环）｜ `RLIMIT_AS=128MB`（内存炸弹）｜ `RLIMIT_FSIZE=0`（禁止写文件）｜ `RLIMIT_NPROC=16`（fork 炸弹）｜ `RLIMIT_NOFILE=32`
3. `env={}` 空环境继承 —— 子进程拿不到任何 API key/token
4. **AST 静态预检**（执行前，拒绝即返回错误不进子进程）：
   - 禁 `import os/sys/socket/subprocess/shutil/ctypes/importlib` 及 `__import__`、`eval`、`exec`、`open`、`compile`
   - 禁 dunder 链：`__class__`/`__subclasses__`/`__globals__`/`__builtins__`（防沙箱逃逸经典路径）
5. 白名单 import：`json re math statistics datetime itertools collections csv io textwrap decimal fractions`
6. 超时 `wait(timeout=5)` → `kill()`；stdout 截断 4KB

**权限**：默认 `ask`（复用现有弹窗）；用户在弹窗勾选"本次会话不再询问"→ 会话级放行（不写永久 allow）。

**验收用例（14 个，进回归门禁）**：
- 正 8：复利计算 / 两组数据统计对比 / CSV 字符串透视 / 日期差 / 进制转换 / 简单模拟 / JSON 变换 / 文本频率统计
- 攻 6：`import os` / `__import__('os')` / `getattr(builtins)` 逃逸链 / `open('/etc/passwd')` / while True 死循环 / 递归内存爆炸 —— **全部须被拒绝或安全终止，0 逃逸**

### T1.2 工具运行时注册 + MCP 热加载

**接口契约**：
```python
# Agent 在任务中定义新工具（受限 DSL，非任意代码）：
register_dynamic_tool({
  "name": "extract_pricing",          # 动态工具前缀 dyn_ 防与内置冲突
  "desc": "从知识库片段中抽取含金额的句子",
  "params": {"query": "str"},
  "pipeline": [                        # 管道 = 已注册原语的声明式组合，杜绝任意执行
    {"tool": "search_kb", "args": {"query": "$query"}, "as": "hits"},
    {"tool": "run_python", "args": {"code": "...解析 hits..."}, "as": "out"}
  ],
  "ttl_tasks": 1                       # 动态工具仅存活本次任务，防注册表污染
})
```
- 动态工具生命周期 = 单任务（`_normalize_args` 复位机制旁新增 registry 快照/回滚）
- MCP 热加载：`POST /api/agent/mcp/reload`（admin）→ `mcp_client.reload()`；mcp.json 修改后不重启生效
- 幻觉工具防护补强：调用未注册名时返回完整可用工具列表 + 动态注册引导（现返回报错，引导不足）

### T1.3 工具原语化

- 原语集：`kb_search / doc_read / dir_list / web_search / web_read / calc(=run_python) / render_doc / competitor_search`
- 复合工具改为管道声明（JSON 映射），`generate_doc = render_doc ← kb_search` 等
- **兼容承诺**：8 个内置工具名保留为别名，50q 与 100 例矩阵 0 回归（门禁）

### T1.4 自主化开关 `autonomy=high`

```python
harness.run(..., autonomy="high")   # 路由层从工具栏读取，默认 "standard"
```
- high 模式变化：跳过 `classify_intent` 短路与 `_answer_general_chat`（全部进 ReAct）、跳过 `_force_*_step` 强制步、保留权限闸门/预算/反思
- **降级协议**：连续 2 次计划失败（plan 为空或步全败）→ 自动回退 standard 完成本轮 + 结果卡标注"已降级"
- 前端：工具栏加"自主模式"开关（默认关，与"深度思考"开关同款交互）

## 3. WS2 经验记忆闭环（详细规格）

### T2.1 `agent_episodes` 表（db_init 照 agent_sessions 模式）

```sql
CREATE TABLE IF NOT EXISTS agent_episodes (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id INTEGER NOT NULL,
  session_id TEXT NOT NULL,
  goal TEXT NOT NULL,               -- 用户原始目标（≤500 字）
  goal_vec BLOB,                    -- BGE 768 维 float32
  plan_json TEXT NOT NULL,          -- 计划快照 [{step, tool, args_digest}]
  trajectory_json TEXT NOT NULL,    -- [{step, tool, elapsed, ok}]
  clarify_rounds INTEGER DEFAULT 0,
  rerun_count INTEGER DEFAULT 0,
  success INTEGER NOT NULL DEFAULT 0,   -- 合成信号，见下
  feedback INTEGER DEFAULT 0,           -- 1 点赞 / -1 点踩 / 0 未评
  outcome_summary TEXT,                 -- 结果摘要 ≤500 字
  created_at TIMESTAMP DEFAULT (datetime('now','localtime'))
);
CREATE INDEX idx_episodes_user ON agent_episodes(user_id);
```

**写入时机**：`run()` 收尾处（成功与失败都写）——失败经验同样有教学价值。
**success 合成规则**：`success = result.success AND rerun_count<=1 AND feedback>=0`；feedback 在弹出后异步 UPDATE 回写。

### T2.2 质量信号采集

- 显式：结果卡 footer 加 👍/👎（`POST /api/agent/episode/feedback {session_id, value}`，仅 Agent 视图，不动经典模式）
- 隐式：`rerun_count`（已有）、`clarify_rounds`（已有）、plan 步失败率（`_step_results` 已有）

### T2.3 经验检索注入

**流程**（`run()` 首轮构建 prompt 时，standard 与 high 都生效）：
1. `goal` embed（复用全局 BGE，<50ms）
2. `agent_episodes WHERE user_id=? AND goal_vec IS NOT NULL` 全量取回内存余弦 top3（episodes 量级 ≤几百，无需向量库；>1000 条时再引入 sqlite-vss）
3. 相似度 <0.60 丢弃；剩余按 [success=1, feedback=1] 优先排序
4. 注入块（≤600 字）：
```
【过往相似任务经验】
· 2026-09-01「智慧园区竞品对比」（相似度 88%，成功）：先 search_kb 拿成本数据，
  再用 run_python 对齐口径，最后 render_doc。教训：两家口径不同须先统一单位。
· 2026-08-20「某制造业方案」（相似度 71%，失败重跑 2 次）：直接生成文档导致
  返工——先出计划与用户确认再执行。
```
**验收**：A3 对照实验——同 10 个目标隔 48h 执行两次，第二次注入经验：成功率/时延/重跑率三项对照。

### T2.4 playbook 提炼（P2）

- 每日凌晨离线任务（与 WS3 调度器同进程）：取 30 天内 success=1 且轨迹模式聚类后出现 ≥3 次的 episode → LLM 提炼 playbook JSON `{triggers, strategy_points, pitfalls}` → **存 staging 表，人工在管理页审定后**入现有技能包机制（match_capability 挂载，零代码扩展）

## 4. WS3 主动式长程任务（详细规格）

### 数据模型

```sql
CREATE TABLE IF NOT EXISTS agent_jobs (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id INTEGER NOT NULL,
  name TEXT NOT NULL,
  prompt TEXT NOT NULL,             -- 每次执行的完整指令
  cron TEXT NOT NULL,               -- 标准 5 段 cron（创建时经 LLM 归一 + 预览确认）
  budget_tokens INTEGER DEFAULT 50000,
  state TEXT NOT NULL DEFAULT 'active',   -- active/paused/done/failed
  consecutive_failures INTEGER DEFAULT 0,
  last_run_at TIMESTAMP, next_run_at TIMESTAMP,
  created_at TIMESTAMP DEFAULT (datetime('now','localtime'))
);
CREATE TABLE IF NOT EXISTS agent_job_runs (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  job_id INTEGER NOT NULL,
  ok INTEGER, tokens_used INTEGER, elapsed REAL,
  result_digest TEXT,               -- ≤800 字摘要
  notify_status TEXT,               -- sent/failed/skipped
  created_at TIMESTAMP DEFAULT (datetime('now','localtime'))
);
```

### 调度器

- `APScheduler BackgroundScheduler` 挂 FastAPI lifespan（生产 uvicorn 单 worker，无多进程重复调度问题——部署前复核 worker 数）
- 每 job 执行 = 独立线程 + `asyncio.run(harness.run(prompt, session_id=f"job_{id}_{ts}", user_id=...))`，**强制 `disable_web_search` 继承 job 配置，token 计量走 usage_logger**
- 护栏：单次执行超 `budget_tokens` → 中断标记 partial；`consecutive_failures>=3` → job 自动 paused + 飞书通知；每用户 active job 上限 5 个
- 重启恢复：startup 时按 `next_run_at` 重新注册全部 active job（错过窗口顺延不补跑，防风暴）

### 创建与触达

- 创建：对话内"每天早上九点帮我盯 XX"→ 拦截链新增 `_JOB_RE`（agent_routes 层，与 CRM 拦截同构）→ 强制步抽取 `{name, cron, prompt}` → **前端确认卡片**（展示 cron 人话解释 + 预算）→ 确认才建
- 触达：run 完成 → 结果摘要经飞书机器人推送（标题/摘要/深链 `cloudsol.cn/#agent?job=<id>`）
- 管理：侧栏新增"定时任务"入口（列表/暂停/删除），P2 前端交付
