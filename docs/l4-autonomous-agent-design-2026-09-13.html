1. 定位：两层都要 —— 通用底座 + 垂直售前包

目标是完全自主的售前 Agent：不是"能力面铺得很宽的通用助手"，也不是"只能按固定流程跑的脚本"。 落地形态是双层：

层是什么与行业的关系
通用底座自主循环、计划/待办机制、子体派生、记忆 API、工具注册与自扩展、守卫与审计行业无关。换包即另一个垂直
垂直售前包售前资产、售前工具、售前角色子体、售前阶段语义只服务售前

判据：自主度是手段，售前闭环是本体。 一个任务从线索到交付物 + 推进建议，全程不需要人喂下一步。

自主度阶梯（现状 → 目标）

档特征位置
L0 流水线宿主写死步骤（legacy 两阶段，今天线上默认）—
L1 模型选工具仅 solution/competitor 进循环；短程（均 5 轮）；计划不绑定← 现状（S4 验证到此）
L2 计划绑定 + 全意图计划成为有齿的待办；所有意图进循环目标 P0/P1
L3 长程自愈压缩后续跑；错误自愈；自写记忆目标 P2
L4 自扩展委派自建工具/技能；派生子 agent；按需挂 MCP目标 P3

能力归属层理由

售前工具（search_kb / search_competitor / cost_calc / CRM / 招标线索）垂直包（经 MCP + 工具注册表挂载）领域动作

4. P0 详细设计（计划绑定）—— 已实现

4.1 语义变更

计划从叙述性（给用户看的进度视图，明确"不约束执行"）改为有齿的待办：

  • 终稿交付前，计划里每一步必须闭合：done，或 skipped（必须带原因）。
  • 有未闭合项时，宿主不接收终稿，把未闭合项退回给模型，由模型自决：补做，或如实标 skipped。
  • 新增 skipped 状态 = 允许放弃，但必须显式声明——不允许"默默不收尾"。

4.2 边界纪律（这不是宿主夺权）

宿主只做一件事：查「模型自己发布的计划有没有未闭合项」这一个事实。然后给模型两个选项。

宿主不做：

  • ❌ "某工具属于哪一步"的归属推导（那正是架构文档 §8 要删的 _tool_to_plan_index）
  • ❌ 规定执行顺序（顺序仍完全由模型决定）
  • ❌ 替模型决定补做还是跳过

4.4 防死锁

最多交回 AGENT_PLAN_CLOSE_MAX_RETRY（默认 2）次；超出则接受终稿并打告警标记—— 原则：宁可告警，不可卡死。代价：仅在发生漂移时多 1–2 次 LLM 调用。

4.5 验收

  • 离线：.workbuddy/Temp/fc_runtime_smoke.py 44/44 通过（新增 8 项 P0 检查）
    • T10 计划留 1 步未闭合 → 断言：拦截 1 次、模型改为 skipped 后交付、共 5 次 LLM 调用
    • T10b 模型死不闭合 → 断言：拦截恰为上限 2 次、仍产出终稿（不死锁）
    • 附带验证：计划全闭合后 thinking 自动降档（enabled → disabled），证明 skipped 被正确当作闭合信号
  • 新增指标 A11 计划收敛率 = 交付时计划全闭合的运行 / 发布过计划的 FC 运行，目标 ≥0.90
  • 待办：本地活测（需拉起重启服务）——给一个多步售前任务，确认出现「模型自己发现漏步并补上」的行为，而不是靠改提示词

4.6 回退

AGENT_PLAN_CLOSE_ENFORCE=0 + restart → 行为回到今天。经典模式与 legacy 管线一行未动。

7. 风险与前提

#风险 / 前提对策
R1模型是天花板：L1 均 22s/5 轮；L3/L4 是分钟级 + 几十轮，DeepSeek 长程稳定性未知D-C 先实测；必要时换底座或加"自检-重规划"回路
R2成本与时延预算守卫 + 分级放权；长任务单列预算策略
R3公开站 + 写权限 = 真实攻击面（cloudsol.cn）守卫不可省：预算熔断、权限门、全量 trace、一键关闭
R4计划闭合门可能被"虚标 done"绕过POLICY 明确禁止 + 提示词要求如实标 skipped；后续可用"工具序列 vs 计划"抽检（需谨慎，勿变成宿主夺权）
R5改自身代码 / 对外发送不可回滚§2 分级放权，绝不一步到位
R6垂直包与底座耦合，日后换垂直被污染§3 边界纪律：领域语义只准进包，不准进底座

回退（全局）：AGENT_RUNTIME=legacy + restart，或前端 ⚡ 自主开关关闭（双门禁 runtime=fc 且 autonomy=high）。
